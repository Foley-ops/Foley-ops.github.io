# foley-ops.github.io

Personal academic website of Nicholas Foley. It's a multi-page static site
generated by Jekyll 4 and deployed for free to GitHub Pages by a GitHub Actions
workflow (`.github/workflows/pages.yml`). Every push to `main` rebuilds and
redeploys it, and you can watch each run in the repo's **Actions** tab.

## Deploying

**One-time setup:** in the repo's **Settings → Pages**, under *Build and
deployment*, set **Source: GitHub Actions**. The old "Deploy from a branch"
setting ignores the workflow.

**After that, just push to `main`.** The workflow builds the site, checks its
links, and deploys it. It takes about a minute or two, and you can watch it in
the **Actions** tab. If a run fails, click it to see which step failed and why.
To redeploy without changing anything, open **Actions → Deploy site to GitHub
Pages → Run workflow**.

> If you move the site (another account or a custom domain), update `url:` in
> `_config.yml` and the `--swap-urls` address in the workflow.

## Add your photo and CV

| What  | Put the file at | Then set in `_config.yml` |
|-------|-----------------|---------------------------|
| Photo | `assets/img/profile.jpg` (a portrait about 600×720; 5:6 crop) | `avatar: /assets/img/profile.jpg` |
| CV    | `assets/files/Nicholas_Foley_CV.pdf` | `cv_pdf: /assets/files/Nicholas_Foley_CV.pdf` |

Until they're set, the site shows an "NF" monogram and hides the
*Download CV* buttons. The HTML CV page works either way.

## Where everything lives

Most updates mean editing one YAML file. You shouldn't need to touch any HTML.

| To change…                         | Edit |
|------------------------------------|------|
| Name, title, email, advisor, photo, CV PDF | `_config.yml` → `author:` |
| Home page bio and interest chips   | `index.md` |
| About page                         | `about.md` |
| News items (home page)             | `_data/news.yml` (newest first) |
| Publications (page, home, CV)      | `_bibliography/papers.bib` |
| Research directions                | `_data/research.yml` |
| Projects                           | `_data/projects.yml` |
| CV page sections                   | `_data/cv.yml` |
| Profile links (Scholar, ORCID, …)  | `_data/links.yml` |
| Nav menu                           | `_config.yml` → `nav:` |
| Colors / fonts / layout            | `assets/css/main.css` (color tokens are at the top) |

## Publications (BibTeX)

All publications live in **`_bibliography/papers.bib`**. The
[jekyll-scholar](https://github.com/inukshuk/jekyll-scholar) plugin turns them
into the Publications page, the "Selected publications" list on the home page,
and the list on the CV page. To add a paper, paste its BibTeX entry into the
file and push.

- **The entry type picks the section:** `@inproceedings` goes under Conference
  papers, `@article` under Journal articles, `@misc` under Preprints (arXiv's
  "Export BibTeX" already uses `@misc`), and `@phdthesis` under Theses. Entries
  are sorted newest first by `year` and `month`.
- **Write authors as** `Last, First and Last, First`. Your name is bolded
  automatically.
- **Optional extra fields:** the site reads these, and they're stripped from the
  BibTeX that visitors copy.

  | Field | What it does |
  |-------|--------------|
  | `abbr = {NeurIPS 2027}` | Badge text (otherwise "Conference", "Preprint", …) |
  | `selected = {true}` | Also show it on the home page |
  | `tldr = {...}` | One- or two-sentence summary under the entry |
  | `arxiv = {2609.30592}` | arXiv button; the title links to arXiv |
  | `pdf`, `code`, `slides`, `poster`, `video`, `website` | Buttons (full URLs) |
  | `doi = {10.1109/...}` | DOI button (a standard field) |

- **BibTeX gotchas:** `%` starts a comment and `~` is a non-breaking space,
  so avoid them in titles and summaries. Wrap acronyms in braces, e.g. `{DNN}`.
- Research-page "Related" links are set in `_data/research.yml`. Point them
  at `/publications/#<bibtex-key>`.

## Link checking

After each build, the workflow runs
[html-proofer](https://github.com/gjtorikian/html-proofer) on the generated site:

- **Internal links and images** (pages, `#anchors`, files under `assets/`).
  If any are broken, the build fails, the site isn't redeployed, and the
  Actions tab shows which link broke.
- **External links** (arXiv, GitHub, …) are checked too, but the result is
  only reported in that step's log. Other sites go down or block bots, so they
  don't block a deploy. LinkedIn, Google Scholar, and ResearchGate are skipped
  because they always block automated checks.

**YAML gotcha:** wrap any line that contains `: ` (colon and space) in quotes,
for example `- "Advisor: Dr. X"`.

## Preview locally (optional)

```bash
bundle install
bundle exec jekyll serve --livereload
# → http://localhost:4000
```

The `Gemfile` lists the same Jekyll 4 and plugin versions the workflow uses,
so a local build matches the live site. Because the build runs in Actions, you
can add any Jekyll plugin to the `Gemfile`; the old GitHub Pages plugin
allowlist no longer applies.

## Layout

```
.github/workflows/pages.yml  build + deploy (GitHub Actions)
_config.yml          site settings + your info
_bibliography/       papers.bib — publications
_data/               news, research, projects, CV, links (YAML)
_layouts/            default, home, page, about; bib* = publication entry templates
_includes/           header, footer, icons, publication helpers, …
assets/css/main.css  all styles (light + dark)
assets/js/           theme toggle, BibTeX toggles, research-page sphere
assets/fonts/        self-hosted Newsreader + IBM Plex (SIL OFL)
index.md about.md research.html publications.html projects.html cv.html 404.html
```
